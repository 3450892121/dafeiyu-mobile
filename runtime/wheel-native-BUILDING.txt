Corresponding source for libraries and copyleft packages inside Python wheels

Scope
-----
The wheel-native-sources.lock.json at the root of this source ZIP binds each
component to the original wheel SHA256 and exact redistributed member hashes.
The original wheels remain unmodified in the APK. Sources and recipes under
wheel-native/ have their own fixed public URLs, sizes and SHA256 in that lock.
This supplement is separate from the Ubuntu .dsc/source packages in sources/.
Ubuntu's GCC sources do not replace the distinct AlmaLinux GCC runtime below.

ALSA 1.2.12 (LGPL-2.1-or-later)
-------------------------------
sherpa_onnx's wheel dynamically bundles libasound-eeac1cd9.so.2.0.0. The included
official sherpa-onnx v2.0.1 build-wheels-aarch64 workflow explicitly clones
alsa-project/alsa-lib at v1.2.12 and runs ./gitcompile before auditwheel repair.
The ALSA v1.2.12 source archive includes gitcompile, configure.ac, Makefile.am,
library source, original notices, and COPYING. Use an ARM64 Linux build host
with the Autoconf/Automake/Libtool development tools and follow that workflow;
./gitcompile builds the shared library. The aserver utility in the source has
separate GPL terms; this wheel binds to the LGPL libasound shared library.

You may build and substitute an interface-compatible libasound. auditwheel's
hashed filename/SONAME is relocation, not an added restriction: either retain
that compatible wheel member name/SONAME, or use auditwheel to repair a wheel
against your rebuilt library. Repack the wheel and rebuild your APK as below.

lxml 6.1.3 with GNU libiconv 1.18 (library LGPL-2.1-or-later)
---------------------------------------------------------
The lxml wheel statically contains GNU libiconv 1.18. Full lxml source, generated
C sources, setup.py, setupinfo.py, pyproject.toml and buildlibxml.py are supplied
in its official sdist, together with the fixed upstream wheel workflow. The
other fixed build inputs are also supplied: libxml2 2.14.6, libxslt 1.1.43 and
zlib 1.3.2. Their original permissive notices remain in those source archives.

For replacement or relinking, use the included complete lxml source as the
work that uses libiconv, together with your modified libiconv source. Build on
an ARM64 Linux build host with the development tools in lxml's upstream wheel
workflow. The supplied pyproject.toml selects STATIC_DEPS=true and the exact
ZLIB_VERSION, LIBICONV_VERSION, LIBXML2_VERSION and LIBXSLT_VERSION above.
Put the supplied dependency archives in the lxml tree's libs/ download cache,
or arrange the equivalent local buildlibxml.py inputs, then build that source
with CPython 3.12 and the upstream cibuildwheel 4.2.0 recipe. A normal local
static build can also use STATIC_DEPS=true and those same version variables
with pip wheel, after installing its declared Cython/setuptools build tools.

This source form permits rebuilding and relinking lxml with a changed LGPL
library; it does not require accepting a prelinked object as the only input.
Replacing a static library requires rebuilding the extension, rather than
dropping an unrelated .so beside it. Do not substitute a later source release
for the corresponding source of the unmodified distributed extension.

NumPy's libgfortran (GPL-3.0-or-later WITH GCC-exception-3.1)
---------------------------------------------------------
The bundled libgfortran is from the exact AlmaLinux source RPM
gcc-8.5.0-28.el8_10.alma.1.src.rpm, not Ubuntu GCC 14. The library matches the
official AlmaLinux aarch64 RPM's GNU build-id and executable/data section hashes
recorded in the lock. The source RPM's SHA256 was checked against AlmaLinux's
official vault source repodata. It includes GCC's original source archive,
distribution patches, gcc.spec and other source inputs: 63 payload files.

On an AlmaLinux 8.10 ARM64 build host, install the distribution's standard RPM
development tools and the BuildRequires declared by the supplied gcc.spec, then
use rpmbuild --rebuild --target aarch64 with this source RPM (or the equivalent
documented mock build environment). Source unpacking and compilation belong
on a build computer; do not execute this recipe in the phone's app environment.
For compatible library replacement, retain the wheel's relocated member path
or regenerate its auditwheel repair. The full GCC exception and GPL text are
preserved; this exception does not make the runtime library itself MIT.

Eigen compiled into ONNX Runtime (MPL-2.0)
----------------------------------------
The actual ONNX Runtime library contains compiled Eigen template code. The
source supplement includes exact Eigen commit
1d8b82b0740839c0de7f1242a3585e3390ff5f33, not an assumed later release. Its
archive SHA1 matches the fixed ONNX Runtime 1.28.2 deps.txt, and the lock also
records SHA256. The two original patches s390x-build.patch and
s390x-build-werror.patch, and the fixed eigen.cmake recipe are included. Apply
those patches as specified by the recipe. The original MPL text and all source
copyright notices are preserved. For a changed Eigen build, use that source
with the supplied patches and your changes, then rebuild ONNX Runtime using
Microsoft's public source at the exact 1.28.2 commit recorded in the lock and
its documented ARM64 procedure. ONNX Runtime itself remains MIT; its license
and generic third-party notice provenance are separate from the actual
MPL-covered Eigen source/patches. No optional backend is inferred from a
generic notice list.

Python packages supplied in source form
--------------------------------------
bilibili-api-python 17.4.2 (GPL), setuptools 84.2.1 including its vendored
autocommand 2.2.2 (LGPL), and certifi 2026.10.23 (MPL-2.0) retain their Python
source/data and original license notices in the wheels. Their official fixed
sdists are additionally supplied for the preferred source and packaging
scripts. The standalone original autocommand sdist is also supplied. Preserve
setuptools' own source and vendoring configuration when rebuilding its copy;
the standalone autocommand source alone does not describe setuptools' layout.
Follow each sdist's pyproject.toml/setup.py and original license. No proprietary
configuration, credentials, account database or runtime data is included.

Notices and scope exclusions
---------------------------
ONNX Runtime's exact upstream binary archive is used only as provenance for
its original LICENSE and ThirdPartyNotices, retained with the app and this
source supplement. License/notice-only components are identified separately
from the libraries requiring corresponding source. The actual Pillow wheel
does not contain FriBidi or libimagequant implementations; its runtime-loading
FriBidi shim has its own permissive license. Do not infer included libraries
solely from an upstream generic SBOM or license appendix.

Rebuild, replacement and signing
-------------------------------
You may inspect, debug changes to, modify, rebuild, replace and relink the
applicable free-software components under their original licenses. This
project imposes no extra restriction on reverse engineering needed to debug
such modifications. Dynamic wheel libraries can be substituted with compatible
rebuilds; static libiconv can be replaced by rebuilding the supplied lxml work.

Use wheel unpack/pack or the upstream packaging tools to regenerate a valid
wheel, including RECORD. In your own project build, replace the matching wheel,
update its fixed manifest/bindings and generated resources, then rebuild the
APK using the project build instructions. You may use your own Android signing
key. The original publisher's Android signature is not required to build your
own modified APK; Android's normal upgrade/signing rules still apply. Do not
claim modified wheel bytes match the original upstream SHA256. No extra
integrity mechanism prevents the owner from changing these public source
files, rebuilding the manifests and substituting these libraries in their
own build. App data can be exported/imported using the documented encrypted
backup mechanism, subject to its stated scope.
