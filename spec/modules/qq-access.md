# QQ 接入

目标：让新 QQ 小号在手机本机收发消息，并为大脑提供稳定、准确的消息来源与发送回执。

范围：小号登录、私聊和群聊事件、引用、表情、图片、文件、历史消息、空间接口与重连。候选实现和差异见 `../qq-access.md`，不能在候选未验收时宣称已支持。

输入：用户为本项目新建的小号登录确认、所选运行内核、真实事件及其回执。

输出：统一事件、明确发送结果、有限重连状态；验证挑战或账号被踢必须停下等待用户处理，不能不断重登或轮换设备身份。

非目标：不接管原号，不调用原项目服务，不通过模拟点击操作 QQ，不声称拥有腾讯未提供的风控豁免。

依赖：原生应用承载本机运行层，本地数据模块隔离登录资料，大脑消费消息事件。

接口差异必须显式适配，例如 SnowLuma `get_file` 不覆盖普通群文件下载，不能照搬原实现的兜底逻辑。

NapCat HTTP 事件上报使用 `X-Signature: sha1=<HMAC>`，接收端须用本实例密钥对原始请求字节验签，兼容分块传输并限制请求大小；缺少或错误签名不得入队。原有 Bearer 鉴权保留，不能为了接通回调关闭鉴权或将凭据写入日志。

覆盖更新须保留本实例 QQ 登录资料及设备信息。界面目录与内核登录目录分别固定；已有登录目录优先沿用，不为更新清空、搬动或重建。存在多个无法确定的旧目录时暂停并明确报告，不猜测。恢复检查只返回指定小号是否有可用的快速登录记录，不输出票据、其他账号或数据库内容；不能把文件存在当作在线或会话有效。

收发诊断不能依赖 QQ 在线。只读检查本实例已配置会话的收发计数、接话/沉默次数、模型成败和固定错误类别；不显示聊天正文或凭据，不发消息、不调模型、不恢复登录。统计起点依据最近一次大脑状态快照的时间及 uptime，停止后不得用当前时间计算而漏掉故障前记录。回调处理仅保存状态码和消息类型计数；诊断写入失败不能影响正常收发，历史记录不能冒充本次接收证据。
