# 验收标准

交付必须附测试证据。实现与验收对照分开进行；无命令输出、设备日志或实际回执的项目必须写“未验证”。后续完整功能不能因骨架检查通过而自动打勾。

## A：初始化工程

| 编号 | 判据 | 执行与证据 |
|---|---|---|
| A01 | 规则章节完整，包含记忆与交接、收尾、安全约束；规格与用户选择一致 | `node tools/check-project.mjs` 输出 `project checks passed`；人工对照用户问卷及后续更正 |
| A02 | 功能清单有唯一编号、参考源码、是否允许省略及逐项证据要求 | `node --test tests/*.test.mjs` 中目录与清单检查通过 |
| A03 | APK 的资源仅从清单生成，所有未实现功能都显示待实现 | `node tools/prepare-assets.mjs --check` 无差异；检查应用源码及生成资源 |
| A04 | 缺少手机 QQ 内核时不显示已登录或运行成功 | 运行纯 Java 就绪判定检查，覆盖缺内核、未经验证、被踢及挑战；见 `tools/build-apk.ps1 -TestOnly` |
| A05 | 仅构建本项目，无依赖原服务器、原账号或原凭据 | 工程检查无原服务地址和真实凭据；清单来源不等于运行依赖 |
| A06 | 生成单个具有有效签名的 APK，包含启动图标与中文界面 | `tools/build-apk.ps1` 成功；`apksigner verify` 成功；`aapt dump badging` 显示本项目包名及启动 Activity |
| A07 | 在免 Root 安卓真机安装并从图标打开，显示设备检查与未接入状态 | 记录机型、安卓版本、安装返回与界面；没有连接设备时只能写未验证 |
| A08 | Git 身份沿用现有配置，分支为 main，仅提交本项目文件 | `git status --short`、`git log --oneline` 与 `git branch --show-current`；敏感信息扫描通过 |
| A09 | 参考目录未被本次操作写入，其他项目未被访问或修改 | 记录只读范围；本项目工具禁止以参考目录作输出路径；不把其他人并发修改归因于本次任务 |
| A10 | README、许可及第三方登记与最终代码一致，交接不混入规则 | 重读相关文件、核对命令和路径；检查无占位和虚构产物 |

## B：独立运行的必要条件

| 编号 | 判据 | 执行与证据 |
|---|---|---|
| B01 | 新小号在手机本机成功登录并收发；不使用原号 | 用户指定小号及会话后记录登录和收发回执，不记录密钥 |
| B02 | 电脑和原服务器不可用时，手机仍完成对话、落库与提醒 | 在明确隔离原服务的网络条件下操作并记录请求目标、手机进程及实际结果 |
| B03 | 同一 App 内完成 QQ 运行层启动与管理，无需安装第二个 App | 干净手机上安装和初始化；核对 QQ 内核的 ABI、来源、版本和许可 |
| B04 | 熄屏至少 2 小时，网络切换后有限恢复；重启后保留本实例资料 | 记录设备电池设置、前后台、断网恢复和重启证据；不以模拟测试代替 |
| B05 | 验证挑战、被踢和风控提示暂停自动登录及主动动作 | 隔离模拟覆盖停止分支；真实发生时核对日志，不主动触发风控 |

## C：功能复刻

`features.json` 的每条 `required` 功能分别验收。先运行对应隔离场景，再在用户指定范围完成真实交付；没有真实回执时写未验证。语音相关能力、翻唱仅在有证据说明手机不适用时按用户授权省略，并报告原因；不连带省略点歌、文件分享或视频理解。

## D：真机前完整实现

用户要求先完成代码，手机最后提供。真机前必须交付：私有运行层、应用内初始化、QQ 接入及管理、大脑和工具源码、独立本地数据与备份恢复、可用设置界面、逐项实现来源与隔离证据。运行层原生产物和下载源必须实际存在并校验，不能只有下载地址占位。

执行 `tools/test-runtime.ps1`，覆盖新库初始化、独立配置、消息归属和隐私、记忆、成长、日记和梦、权限、文件制作解析、工具回执、公开操作门控、备份恢复、运行层归档与配置生成。使用临时目录、假 QQ 和假模型，不请求真实账号或 API Key。执行 `tools/build-apk.ps1` 编译并验证最终 APK、资源及签名。

功能状态用 `implemented` 表示有实际源码及隔离证据但等待手机验收；仅真机通过才用 `verified`。允许省略的能力必须写出原因；不得将缺环境、缺凭据或未验证伪造为成功。

最终回复分别报告初始化、真机前实现、真机待验收。电脑回归只在隔离场景执行；用户提供手机并明确账号、会话范围后，真机联调仅在该范围执行。公开发布和公开平台互动仍须分别取得对应授权。

## E：内置运行组件与公开下载入口

新增本节是因为用户要求普通用户无需代理取得首次运行组件，并指出仓库首页不能明确看到安装包；不降低B/C的真机判据。

| 编号 | 判据 | 执行与证据 |
|---|---|---|
| E01 | 可再分发组件实际随最终APK内置，包含Ubuntu基础归档、ARM64系统依赖闭包、目标Python wheels、完整NapCat及CPU模型 | 内置清单和每项来源/大小/摘要存在；最终签名APK逐项哈希、路径及大小验证；不以下载URL或空目录代替 |
| E02 | 系统/Python/模型初始化没有GitHub、Ubuntu、PyPI在线回退，缺文件/损坏即失败 | 隔离覆盖缺归档/坏摘要/不兼容依赖；APT仅file源且保留官方签名验证，PIP仅内置wheel；目标Linux依赖闭包和包索引校验，不拿Windows环境解析代替 |
| E03 | QQ未未经授权内置，唯一客户端归档联网步骤为腾讯官方HTTPS固定下载 | 检查最终包无QQ归档，锁定官方来源与摘要；界面和README明确此例外及AI/登录联网要求，不能称完全离线 |
| E04 | 第三方许可及对应源码随公开二进制可获取 | 固定NapCat/模型许可全文、Ubuntu/依赖版权和对应源码清单/获取方法齐备；原生GPL/LGPL来源及替换说明保留；不将专有QQ改标开源 |
| E05 | 仓库首页和发布页明确可见测试版APK入口，APK、项目源码、原生对应源码、Linux及wheel库对应源码、摘要清单五个发布附件完整并可下载 | 核对GitHub实际公开展示与附件、源码和校验；如采用普通Release分类以显示右侧版本，标题及正文仍醒目标明测试版，不声称仍为GitHub原生Pre-release标记 |
| E06 | 新包在干净真机完成仅QQ客户端需联网的初始化及真实收发 | 现场证据验证不依赖代理下载组件；无设备时明确未验证，不以资源内置或隔离检查代替 |
